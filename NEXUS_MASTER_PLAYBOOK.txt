1. Strategic Foundation

1.1 What NEXUS Solves

Independent agents are powerful, but separate agents without orchestration create:
- conflicting decisions
- duplicated effort
- incomplete handoffs
- no single source of truth
- no quality gate continuity
- users seeing a product that was never fully validated

NEXUS exists to solve this by turning a collection of specialists into a synchronized operational system. It defines:
- which agents activate
- when they activate
- what they deliver
- what evidence proves completion
- what happens when a phase fails
- what the next handoff must include
- how deployment, QA, and growth operate as a single system

1.2 Core Operating Principles

- Pipeline integrity: no phase advances without passing its gate
- Context continuity: every handoff includes context, artifacts, and requirements
- Parallel execution: independent workstreams run concurrently
- Evidence over claims: proof is required before approval
- Fail fast, fix fast: maximum 3 retries before escalation
- Single source of truth: one canonical specification, one task list, one architecture package
- Hidden complexity is not allowed: if it matters, it is surfaced and tested
- Security and compliance are not add-ons; they are design constraints
- Product strategy is not separated from execution; every phase is linked to evidence and business intent

1.3 Technical Architecture Principle

The build system is designed around a strict internal logic and external simplicity model:

- C11 is the core logic system
- All internal state management, decision logic, safety logic, and critical processing are authored in C11
- C99 acts as the translator layer
- It handles the bridge between substrate/silicon/data access and the C11 logic layer
- It is the translation, serialization, validation, and cryptographic boundary
- The C90 layer is intentionally boring
- It is the user-facing connector layer: low-complexity interface handling, protocol boundaries, standard connection logic, and user/substrate access simplification
- Python is used only for AI/ML, analytics, data science, model assistance, and non-core orchestration tasks
- The database layer is encrypted and treated as a protected system boundary
- The product’s user-facing experience is intentionally minimal and deterministic; complexity belongs inside the logic and translator layers, not in the user layer

This means:
- external UI, protocols, and user interaction remain simple and boring
- internal core logic remains strict, auditable, and deterministic
- AI is strategic support, not the base of the system
- safety, encryption, and correctness come before convenience

│      (Dart, Material Design)        │
└─────────────┬───────────────────────┘
              │ gRPC / Protocol Buffers
┌─────────────▼───────────────────────┐
│      C90 Connection Layer           │  ← Stateless protocol handler
│  (Request routing, validation,      │
│   session mgmt, rate limiting)      │
└─────────────┬───────────────────────┘
              │ Internal C11/C99 API
┌─────────────▼───────────────────────┐
│      C11 Core Logic Layer           │  ← Decision, state, safety
│  (Business logic, orchestration,    │
│   encrypted state management)       │
└─────────────┬───────────────────────┘
              │ Encrypted data boundary
┌─────────────▼───────────────────────┐
│    C99 Translator & Crypto          │  ← Serialization, encryption
│  (Data serialization, encryption,   │
│   database operations, indexing)    │
└─────────────┬───────────────────────┘
              │ Substrate operations
┌─────────────▼───────────────────────┐
│   Database (Encrypted at Rest)      │  ← Persistent encrypted store
│   ├── SQLite (mobile/desktop)       │
│   ├── PostgreSQL (server)           │
│   └── All data encrypted via C99    │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│    Python AI/Analytics Sidecar      │  ← ML inference, analysis only
│ (TensorFlow, NumPy, Pandas, etc)   │
│ Communicates with C11 for context   │
└─────────────────────────────────────┘

1.2 Design Principles

External Interface (Flutter + C90)
- Simple, boring, deterministic
- No business logic exposed
- Minimal state surface
- Predictable error handling
- All complexity is hidden

Internal Core (C11 + C99)
- Strict, auditable, secure
- All business logic is here
- Encrypted by default
- No shortcuts or workarounds
- Safety is non-negotiable

AI Integration (Python)
- Advisory only, never required
- Cannot override C11 decisions
- Runs async, doesn't block user flow
- Used for analysis, recommendations, pattern detection
- Not part of the critical path

1.3 Communication Boundaries

Flutter → C90
- gRPC/Protocol Buffers
- Stateless requests
- No session state in Flutter
- All requests include auth token

C90 → C11
- Internal C API (fast, zero-copy where possible)
- Request validation already done
- Response serialization handled by C90

C11 → C99
- Encrypted data operations
- All state changes go through translator
- C99 handles encryption/decryption

C99 → Database
- Encrypted writes
- Validated reads
- Transaction management
- Index operations

C11 → Python Sidecar
- Async message queue or REST callback
- Context but no control
- Results are suggestions, not commands
